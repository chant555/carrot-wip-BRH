# 크루즈 대기 판단과 회색 표시를 상류 기준으로 복원

2026-11-07 사용자 요청에 따라 해당 동작을 이미 반영된 상류 `0afb2eb32fc47aa3f94e2921467d087deddbba0d`와 맞췄습니다. 이번 작업에서 새로운 상류 커밋을 가져오지는 않았습니다.

## 목적과 변경 범위

사용자는 과거 상류 `8d055419`의 순정 SCC(스마트 크루즈 컨트롤) 메인 자동 켜기 요청이 크루즈를 연결하지 않아도 앞차와 옆차를 표시하려는 목적이었다고 설명했습니다. 로컬 대기 분리와 회색 표시를 제거한 상태를 다시 비교 기준으로 삼습니다.

- 실제 대기 판단의 `_update_canfd_main_enabled`는 변경 전부터 상류와 같았습니다. 아이오닉 5 PE 전용 추가 조건은 앞선 작업에서 제거됐습니다. 상류 자체의 `CAMERA_SCC` 조건은 그대로 유지합니다.
- `_stock_main_cluster`를 삭제하고 `create_ccnc_messages`의 `0x161` 표시 판단을 상류와 같은 `main_enabled = CS.out.cruiseState.available`로 복원했습니다.
- 따라서 순정 `MainMode_ACC`가 켜져 있어도 실제 크루즈 대기 상태가 꺼져 있으면, 로컬 수정으로 열었던 회색 대기 화면은 열리지 않습니다. 실제 대기 상태에 따른 상류 표시는 유지됩니다.
- 순정 메인 자동 요청, 앞차 선택, 순정 코너 물체 전달은 변경하지 않았습니다. 별도 옆차 표시 대체 기능도 추가하지 않았습니다.
- SoftHOLD(독립 정차 유지), 원터치 방향지시등 4회 제한과 나머지 기존 수정은 보존합니다. 저장소 전체를 상류와 동일하게 되돌리는 작업은 아닙니다.

## 로컬 검증

기존 기능 검사 1,343개가 통과했고 기기 전용 의존성이 필요한 6개는 제외했습니다. 별도 상류 비교 검사 2개도 통과했습니다.

1. 실제 대기 판단 함수 전체를 상류와 구문 비교하여 일치를 확인했습니다.
2. 실제 대기·순정 메인·수동 메인 해제·종방향 제어·앞차 유무의 32개 조합에서 생성된 `0x161` 표시 필드가 상류와 일치했습니다. 검사에서는 체크섬과 순환 계수를 제외한 해석된 필드를 비교합니다.

검증 자료는 작업 공간의 `analysis/2026-11-07-stock-display/`에 보존합니다. 기존 회색 표시 검사도 변경된 상류 동작에 맞게 수정했습니다.

## 기기 확인의 범위

이 기록은 로컬 코드와 검사 결과입니다. 이번 변경을 원격 저장소나 C4에 반영하지 않았고, 재부팅·빌드·주행 검사는 수행하지 않았습니다. 마지막으로 확인한 C4 설치 버전은 변경 전 `3791b956`입니다.

후속 기기 비교에서는 LFA(차로 유지 보조)를 켜기 전후의 순정 메인 상태, 실제 크루즈 대기 상태, 순정 코너 입력과 표시 송신을 함께 확인해야 합니다. 물리적인 앞차·옆차 표시 여부는 실제 화면 관찰이 필요합니다. 이번 복원만으로 기존 옆차 표시 문제가 해결됐다고 판단하지 않습니다.
