## 범위와 충돌 해결

사용자 요청에 따라 `14c5398f..90bd49d2`의 5개 커밋을 두 브랜치에 리베이스했습니다. 재조회한 상류 끝도 `90bd49d2845b5dfe1e5e46663c489eb0ca4dde1a`입니다. 이전 끝은 `carrot-wip-brh=8f8b444b5e34a21df21b79236c04f9ef60f953b8`·`carrot-wip-loc=bfa6830e78229589865f76b2e182664241757abd`이며, `refs/backup/20261104-five-brh`·`refs/backup/20261104-five-loc`에 보존했습니다.

반영한 변경은 카메라 기반 크루즈의 순정 MAIN 피드백과 조향 의도 분리, B1 배선 안내, B1 사진 조립·최초 설치 안내, 지정 외장 그래픽 실행 환경의 USB(범용 직렬 버스) 버퍼 순환 수정과 회전 속도 표준편차 기록, 해당 검증 한계 기록입니다. 모델 가중치와 실제 곡선 감속 정책은 바꾸지 않습니다.

두 브랜치 모두 `carstate.py`의 대기 분리 조건 한 곳에서 충돌했습니다. 상류의 `not self.CP.flags & HyundaiFlags.CAMERA_SCC`와 기존 C4의 `carFingerprint != CAR.HYUNDAI_IONIQ_5_PE` 조건을 모두 유지했습니다. 따라서 C4에서는 순정 MAIN 자동 요청이 캐럿 크루즈 대기를 켜지 않으며 운전자 MAIN·SET·RES 버튼 경로를 유지합니다. 다른 카메라 기반 크루즈 차량에는 상류의 조향 의도 분리를 적용하고, 그 밖의 차량은 기존 순정 MAIN 추종 조건을 유지합니다. 초기 자동 활성화 설정과 수동 끔 잠금은 바꾸지 않았습니다.

모의 차량 매개변수에 실제 `flags` 필드를 넣었고, 다른 차량의 순정 MAIN 추종 검사는 카메라 기반 크루즈가 아닌 조건으로 명확히 했습니다. 차종·카메라 플래그·종방향 제어·수동 끔 조합 16개를 추가했습니다.
