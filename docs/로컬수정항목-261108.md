## 1. 아이오닉 5 PE의 독립 SoftHOLD(정차 유지)

아이오닉 5 PE에서 오픈파일럿이 가감속을 제어하고 순정 크루즈 제어 경로를 사용하지 않는 구성에 적용합니다. 크루즈를 연결하지 않은 상태에서도 정차 후 브레이크를 놓으면 홀드를 유지하도록 합니다.

- 전진 기어 전환 후 정상적인 차량 통신 상태에서 시속 18킬로미터 이상 주행한 이력이 필요합니다. 전진 이외의 기어로 바꾸면 초기화합니다.
- 차량 통신과 제어 준비가 끝나야 하며 `AutoCruiseControl`이 0이 아니어야 합니다.
- 전진 기어에서 시속 약 0.36킬로미터 미만으로 브레이크를 약 0.61초 유지하면 준비합니다.
- 새 홀드 진입에는 조향각 절댓값 180도 미만 조건을 적용합니다. 이미 유지 중인 홀드를 조향각만으로 해제하지 않습니다.
- 최초 크루즈 버튼 조작이나 일반 자동 크루즈의 20초 대기는 필요하지 않습니다. 취소 상태와 `SoftHoldOnCancel` 설정에 관계없이 준비할 수 있습니다.
- 가속페달 입력·통신 불량·순정 오토홀드·주차브레이크 등의 차단 조건을 유지합니다.
- 브레이크를 놓아도 홀드 때문에 크루즈를 자동 연결하지 않습니다. 이미 켜진 크루즈를 이 기능 때문에 무조건 끄는 것은 아닙니다.
- 가속페달이나 짧은 브레이크 재입력으로 홀드를 해제합니다. 해제 후에도 자동 연결을 막는 상태를 유지하며, 크루즈를 원하면 기존 버튼을 명시적으로 조작합니다.

별도 준비 상태 `independentSoftHoldReady @113`과 독립 홀드용 정지 제어 경로를 추가했습니다. 독립 홀드의 최종 가속도 요청 두 값은 0으로 제한합니다. 주행 이력을 이미 충족한 채 전진 기어로 주차장에 진입하면 이력은 유지되므로, 모든 주차 상황을 감지하는 기능은 아닙니다.

주요 파일은 `openpilot/selfdrive/car/cruise.py`, `opendbc_repo/opendbc/car/car.capnp`, `opendbc_repo/opendbc/car/hyundai/carstate.py`, `opendbc_repo/opendbc/car/hyundai/hyundaicanfd.py`입니다.

[11-08 갱신] 검토 메모입니다.

- 준비 상태는 `carstate.py`의 `_independent_soft_hold_ready()`가 정합니다. 차종이 `HYUNDAI_IONIQ_5_PE`이고, 오픈파일럿 종방향 제어를 쓰고, 순정 크루즈 제어 경로(`pcmCruise`)를 쓰지 않으며, 제어 준비가 끝났을 때만 참입니다.

## 2. 원터치 방향지시등 유지·차로 변경 예약의 4회 제한

상류의 원터치 승인 대기 기준인 5회·약 4초를 네 번째 점등 또는 입력 후 3.2초 중 먼저 도달하는 시점으로 제한합니다. 실제 램프 점등과 경과시간을 함께 확인합니다.

- 만료되면 소프트웨어의 방향지시등 유지와 다음 차로 변경 예약을 해제합니다. 장애물이 나중에 사라져도 만료된 요청으로 변경을 시작하지 않습니다.
- 이미 진행 중인 차로 변경의 조향은 유지합니다. 새 레버 입력은 새 요청으로 처리합니다.
- 레버를 고정한 지속 입력에는 원터치 상한을 적용하지 않습니다.
- 원터치 대기 설정을 꺼도 상한은 적용하며 외부 방향지시등 유지 요청도 상한을 우회하지 못합니다.
- 필요한 레버·램프 피드백이 없는 차량은 기존 동작을 유지합니다.

[11-08 갱신] 만료 판정은 차로 변경 출발 조건보다 먼저 계산합니다. 그래서 만료되는 순간에 장애물이 사라져도 이미 끝난 요청으로 변경을 시작하지 않습니다. 2026-11-08 상류 반영에서 주변 변수 이름(`stalk_press` → `physical_stalk_press`)이 바뀌어 문맥 줄만 달라졌고, 이 기능으로 더한 줄은 같습니다. 계기판 `0x1EA`의 방향지시등 유지 신호에도 같은 상한을 마지막에 적용합니다.

차량 자체의 원터치 점멸 횟수를 변경하는 기능은 아닙니다. 주요 파일은 `opendbc_repo/opendbc/car/common/blinker.py`, `opendbc_repo/opendbc/car/hyundai/hyundaicanfd.py`, `openpilot/selfdrive/controls/lib/desire_helper.py`, `openpilot/selfdrive/controls/lib/desire_lib/lever.py`입니다.

| 속도 | 상류 평활화 시간 | 로컬 평활화 시간 |

| 시속 25킬로미터 이하 | 0.1초 | 0.3초 |
| 시속 25∼35킬로미터 | 0.1초 | 0.3초에서 0.1초로 점진적으로 변경합니다. |

저속 정체 구간에서 짧은 좌우 흔들림을 줄이려는 목적이며 해당 구간의 조향 반응도 완만해집니다. 주요 파일은 `openpilot/selfdrive/controls/controlsd.py`입니다.

[11-08 갱신] 이 평활화는 차선 모드가 꺼져 모델 곡률을 그대로 쓰는 경로에만 적용됩니다. [11-08 갱신] 사용자 요청으로 상류 `a47fd16e`의 하한 변경을 되돌렸으므로(7번), 지금은 이 평활화만 남아 있습니다.

## 4. 정지 제어의 하한 밴드 선행 적용 취소

상류는 정상 가감속·정지 접근 중부터 `AccelLimitBandLower=0.20`을 미리 적용합니다. 로컬은 선행 적용을 제거했고 정지 접근에서는 0을 사용합니다. 실제 정지 요청·정지 유지 단계에서는 상류와 동일하게 0.20을 사용합니다.

[11-08 갱신] 이 수정은 상류 `0e4ee1bd`를 되돌린 사용자 커밋입니다(2026-10-14). 되돌린 근거는 C4 경로 10a에서 시속 40킬로미터 미만 과감속이 늘어난 기록(가속도와 명령 차이의 하위 5% 값 -0.32, 이전 -0.20∼-0.23)과 사용자의 시내 감속 체감입니다. `create_acc_control_scc2()`가 `apply_canfd_stopping()` 직전에 `AccelLimitBandLower=0.0`을 정하므로, 일반 ACC(적응형 크루즈 컨트롤) 중과 차단 상태에서는 0이고 정지 요청·유지 단계에서만 0.20입니다.

정지 요청 첫 메시지부터 가속도 요청 두 값을 0으로 만드는 동작과 정지 요청 유지 구조는 그대로입니다. 이 차이가 실제 정차 밀림을 해결했다는 결론까지 확인된 것은 아닙니다. 이번에 상류로 복원한 추가 차간 여유 회복과는 별개의 수정입니다.

주요 파일은 `opendbc_repo/opendbc/car/hyundai/hyundaicanfd.py`, `opendbc_repo/opendbc/car/hyundai/stopping.py`입니다.

## 7. [11-08 추가] 저속 행동 곡률 속도 하한 복원

모델의 행동(action) 출력을 조향 곡률로 바꿀 때 나누는 속도의 하한을 상류 `a47fd16e`(2026-11-03, comma `0c40995c` 이식) 이전 값인 1.0m/s로 되돌립니다. 상류의 2.5m/s 하한은 시속 9킬로미터 미만에서 같은 모델 출력의 곡률을 줄입니다. 예를 들어 1.5m/s에서는 원래 값의 약 36%가 됩니다. 이 효과가 3번의 저속 평활화와 겹쳐 저속 회전의 조향이 부족해질 수 있어, 사용자 요청으로 하한 변경만 되돌렸습니다.

| 속도 | 상류(2.5m/s 하한) | 로컬(1.0m/s 하한) |
|---|---|---|
| 1.0m/s(시속 3.6킬로미터) 미만 | 출력 / 2.5² | 출력 / 1.0² |
| 1.0∼2.5m/s(시속 3.6∼9킬로미터) | 출력 / 2.5² | 출력 / 속도² |
| 2.5m/s 이상 | 출력 / 속도² | 출력 / 속도²(같음) |

- 행동 출력을 쓰는 모델에만 해당합니다. `carrot-wip-brh`의 내장 BRH 모델이 대상이며, 행동 출력이 없는 `carrot-wip-loc` 내장 모델은 계획(plan) 경로를 써서 영향이 없습니다.
- 0.3m/s 미만 정차 중 이전 곡률을 유지하는 처리, 가속도·속도 출력, 3번의 평활화는 바뀌지 않습니다.
- 저속 과다 조향을 줄이려던 상류의 효과도 함께 사라집니다. 실제 주행에서 저속 조향 흔들림이 늘지 않는지 확인해야 합니다.
- 상수 `ACTION_CURVATURE_MIN_SPEED = 1.0`을 두었습니다. 상류 검사 `test_action_curvature.py`의 기대값을 1.0 하한으로 바꾸고 0.999·1.0m/s 경계와 저속 곡률 유지 검사를 더했습니다(83개 통과). 상류 하한으로 돌리면 이 중 29개가 실패합니다.

주요 파일은 `openpilot/selfdrive/modeld/modeld.py`, `openpilot/selfdrive/modeld/tests/test_action_curvature.py`입니다.

순정 크루즈 메인 자동 켜기 요청, 앞차 선택과 순정 코너 물체 전달은 상류와 같습니다. LFA(차로 유지 보조)를 켜기 전 옆차 표시를 위한 별도 대체 기능은 추가하지 않았습니다. 로컬 대기 분리 수정의 제거가 상류 자체의 모든 대기 분리 동작을 없앤다는 의미는 아닙니다.
