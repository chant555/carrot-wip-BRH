- 작성일은 2026-10-11이며, 마지막 수정일은 2026-10-13입니다.
- 최초 패치 기준은 상류 `910bd82f`이며, 최신 기기 시험 기준은 `626b887d527ff3c619e885ff65c303255e2933c6`입니다. 이슈와 PR(변경 사항 병합 요청)은 제출하지 않았습니다.

## 패치의 범위와 적용 순서

| 순서 | 패치 | 범위입니다. |
|---|---|---|

| B | [SCons 캐시 잠금·복구](scons_cache_guard-B-910bd82f.patch) | 공통 배타 잠금, 잠금 안의 복구와 용량 정리, 빌드 대기 안내를 담당합니다. A 위에 적용합니다. |
| C | [솔버 자동 감지](solver_autoreset-C-910bd82f.patch) | 손상된 솔버를 감지해 초기화합니다. 배포용 패치는 A+B 위에 적용합니다. |

A에서 솔버 자동 감지 함수, 호출부와 시험을 모두 분리했습니다. C는 공통 초기화 함수를 호출하는 작은 변경이지만, 이번 적용 순서는 A → B → C로 고정했습니다. 자동 삭제가 B의 잠금 보호 아래에서 실행되도록 하기 위해서입니다. A+C 조합은 이번 제출·검증 대상이 아닙니다.

A만 적용하면 동시 실행 보호는 없습니다. 상류의 무잠금 정리 방식을 유지하지만, 복구 경로와 삭제 범위가 달라지므로 위험까지 동일하다고 단정하지 않습니다. A에는 부팅 시 무조건적인 솔버 자동 감지가 없습니다.

## 원래 문제와 근거

기존 분석에서는 Rebuild All을 일곱 번 눌렀지만 모두 성공으로 기록되고 재부팅은 일어나지 않았습니다. 로그인 셸이 `PYTHONPATH`를 덮어써 `scons`가 `libjpeg` 가져오기 오류로 실패했고, 비동기 실행 결과를 확인하지 않는 경로에서는 실패가 사용자에게 전달되지 않았습니다.

환경을 바로잡더라도 최상위 `scons -c`가 종료코드 0으로 끝나면서 실제 정리를 하지 않는 문제가 기록되어 있습니다. 실제 캐시 `/data/scons_cache`를 제거하지 않는 경로도 있어 손상된 생성물을 캐시에서 다시 가져올 수 있습니다. 손상 생성물과 오염 캐시를 수동으로 제거한 뒤 복구한 사례가 있습니다.

10-03의 `scons -c -n --minimal`은 종료코드 0, 삭제 대상 0개였고 대상을 명시하면 373개였습니다. [보존된 출력](../analysis/2026-10-03-upstream/scons-clean-dryrun.txt)을 참고합니다. 이 기록은 당시 기기와 커밋의 결과이며 이번 작업에서 재실행하지 않았습니다.

## A의 동작

버튼은 `/data/rebuild_all.request`를 저장하고 재부팅합니다. 다음 부팅의 런처가 Params 빌드 전에 요청을 처리합니다. 파이썬 요청 함수는 표준 라이브러리만 사용하며 파일 내용을 동기화한 뒤 원자적으로 교체합니다. 별도 리커버리 경로는 `touch`와 `sync`를 사용합니다.

`SConstruct`는 정리 실행 때 `CompilationDatabase`를 등록하지 않습니다. 런처는 `scons -c`가 실패하더라도 빌드 상태 초기화를 시도합니다.

- `.sconsign.dblite`, `/data/scons_cache`, `prebuilt`를 삭제하고 잔존 여부를 확인합니다. 일반 권한으로 삭제하지 못하면 `sudo -n`으로 한 번 더 시도합니다.
- 초기화에 실패하면 성공 플래그를 설정하지 않고 요청을 보존합니다. 실패 화면을 표시하고 후속 빌드로 진행하지 않습니다.
- 초기화에 성공한 뒤 요청을 지웁니다. 요청 삭제 실패도 오류로 처리하며, 로그에서 초기화 완료와 전체 빌드 완료를 구분합니다.
- A에는 공통 캐시 잠금이 없으며 `agnos_init`의 상류 잠금 파일 삭제 동작을 유지합니다. 동시 실행 보호는 B의 범위입니다.

## B의 동작과 이번 수정

1. **`agnos_init`의 무조건적인 `config.lock` 삭제를 B에서 제거했습니다.** 이전의 “부팅 시점에는 다른 빌드가 없다”는 설명을 철회합니다. 저장소 잠금은 캐시 잠금을 대신하지 않습니다.
2. **`heal_scons_cache`를 요청 소비보다 먼저 실행합니다.** 두 경로 모두 Params 빌드보다 앞에 있습니다. 복구가 실패하면 요청 소비와 후속 빌드로 진행하지 않습니다.
3. 캐시 복구는 공통 배타 잠금을 잡았을 때만 합니다. 잠금을 얻으면 남은 `config.lock`을 제거하고 쓸 수 없는 캐시를 정리합니다. 사용 중이면 아무것도 지우지 않고 복구를 건너뜁니다.
4. 잠금 파일은 캐시 밖의 `/data/scons_cache.build.lock`이며 일반 컴퓨터에서는 `/tmp/scons_cache.build.lock`입니다. 읽기 전용으로 열고 잠금을 잡으므로 관리자 소유라도 읽기 권한이 있으면 사용할 수 있습니다. 잠금 파일을 지우거나 교체하지 않습니다.
5. SCons와 Params 빌드는 최대 300초 기다립니다. 경합으로 기다리기 시작하면 이유를 한 번 출력합니다. `build.py`가 수집하는 SCons 출력은 진행 화면에도 전달됩니다. 초기화와 용량 정리는 기다리지 않습니다.
6. Params 준비·빌드·검증·스탬프 기록까지 잠금을 유지합니다. 자식 SCons는 상속된 파일의 식별 정보를 확인하고 같은 잠금을 재사용합니다.
7. `build.py`는 잠금 오류가 나면 캐시를 보존하고 추가 재시도를 멈춥니다. 용량 정리는 같은 잠금 안에서 두 글자 버킷 디렉터리의 파일만 대상으로 수행합니다.

공통 잠금은 이 규약을 사용하는 수정본 사이에서만 보호합니다. 이전 버전이나 다른 포크처럼 잠금에 참여하지 않는 실행을 보호하지는 못합니다. 최초 적용은 기존 빌드가 종료된 상태에서 해야 합니다.

## C의 동작

모델 예측 제어용 솔버의 생성 소스가 비어 있거나 공유 라이브러리에 초기화 심볼 문자열이 없으면 공통 초기화 함수를 호출합니다. 성공한 초기화만 커밋별 스탬프로 기록합니다. 같은 커밋에서 반복 초기화하지 않습니다.

이 검사는 완전한 모듈 정상성 검사가 아닙니다. 정상·손상·파일 부재·초기화 실패·같은 커밋·새 커밋의 시험을 별도로 유지합니다.

## 10-13 후속 정정: 터치 경계 진단과 A+D+E 첫 누름 복구

[후속 진단](../analysis/2026-10-13-touch-followup/validation.md)에서 기존 버튼 아래 경계 밖의 누름을 재현했고, 아래쪽 영역을 넓히자 판정됐습니다. 가운데 영역도 판정됐으며, 같은 읽기 묶음에 누름과 놓음이 들어온 짧은 접촉의 좌표가 보존된 사례를 확인했습니다. 의도한 세 번이 네 접촉으로 잡힌 현상은 원시 입력에도 나타났습니다. 접촉 흔들림의 원인은 미확정이므로 임의의 입력 억제 시간은 추가하지 않았습니다.

[새 D](startup-touch-D-626b887d-v2.patch)는 실제로 로드된 기기용 백엔드에서 입력을 갱신하고 터치·판정·수락·재부팅 기록을 파일에 남깁니다. 일반 컴퓨터에서 중복 갱신하지 않으며, 원시 입력 장치가 열렸는지만으로 백엔드를 판단하지 않습니다. 기록 실패는 복구를 막지 않습니다. [별도 E](startup-touch-usability-E-626b887d.patch)는 버튼 영역을 아래 끝까지 넓히고 작업 거부 시 안내를 표시합니다. 두 패치는 `626b887d` 기준이며 D → E 순서입니다. 이전 D의 원출력과 패치는 당시 시험 근거로 유지합니다.

A+D+E 실제 시험에서는 사용자가 본체 버튼을 평소처럼 짧게 한 번 누른 첫 시도에서 복구됐습니다. 재부팅 후에도 좌표 `(143, 207)`, 리빌드 판정, 요청 수락과 요청 파일 존재가 남았습니다. 캐시 파일 2,521개를 정리한 뒤 약 6.95분 만에 정상 기동했고, 시험용 컴파일 오류가 사라졌으며 두 솔버와 `plannerd` 불러오기가 통과했습니다. 짧은 누름의 길이를 수치로 측정한 것은 아닙니다.

원래 브랜치·기존 수정·모델·캐시·설정을 복원했고 시험 브랜치와 이번 백업·전달 폴더를 삭제했습니다. 운용 코드에는 시험 패치를 남기지 않았습니다. [실기 검증](../analysis/2026-10-13-rebuild-ADE-screen/validation.md), [터치 기록](../analysis/2026-10-13-rebuild-ADE-screen/touch.jsonl), [최종 판정](../analysis/2026-10-13-rebuild-ADE-screen/results.json), [복원 비교](../analysis/2026-10-13-rebuild-ADE-screen/restored-state.json), [백업 삭제](../analysis/2026-10-13-rebuild-ADE-screen/backup-deletion.json)를 연결합니다.

이는 해당 조건의 한 번의 성공이며 모든 짧은 누름이 해결됐다는 보장은 아닙니다. 이전 A+D 첫 무응답의 원인은 여전히 미확정입니다. 앞선 ‘가운데·같은 묶음의 짧은 접촉 미검증’ 표기는 당시 시험 범위이며, 이번 결과로 해당 사례를 보완합니다. A의 동시 실행 보호는 별도 B의 범위입니다. 이슈와 풀 리퀘스트는 게시하지 않았습니다.

## 보류 패치 C·E — 관련 문제가 보고되면 다시 시험 (10-13 기록)
