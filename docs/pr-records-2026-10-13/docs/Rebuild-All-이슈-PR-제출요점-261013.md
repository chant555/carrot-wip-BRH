# Rebuild All 이슈·PR(변경 사항 병합 요청) 제출 요점

작성일은 2026-10-13입니다. 클코의 검토 의견과 보존된 시험 기록을 대조한 별도 제출 준비 문서입니다. 이번 정리에서는 추가 시험, 기기 접속, 패치 수정, 기준 커밋 변경이나 게시를 하지 않았습니다. 아래의 보완 항목은 실행한 작업이 아니라 제출 때 결정할 사항입니다.

## 1. 제출에서 앞세울 문제와 해결

**주된 이슈는 Rebuild All이 실제 빌드 상태와 캐시를 정리하지 못하면서 성공처럼 표시되어 손상된 생성물을 복구하지 못하는 문제입니다.** A는 요청을 저장하고 재부팅한 뒤 런처가 정리하도록 바꾸며, 삭제 실패를 확인하고 실패한 요청을 보존합니다. 정리 완료와 전체 빌드 완료는 구분합니다.

본체 시동 실패 화면에는 별도로 입력 좌표 갱신 누락이 있었습니다. D는 기기용 raylib 백엔드에서 입력을 명시적으로 갱신합니다. 두 번째 수정본에는 재부팅 후에도 확인할 수 있는 터치·판정·요청 수락 기록이 추가됐습니다. E는 버튼 아래쪽 영역과 작업 중 안내를 개선합니다.

제출 제목은 다음처럼 나누는 편을 권합니다.

- A의 이슈: “Rebuild All이 실제 정리 없이 성공으로 표시되어 손상된 빌드를 복구하지 못합니다.”
- A의 변경 요청: “Rebuild All 요청을 부팅 시 처리하고 정리 실패를 보존합니다.”
- D의 별도 이슈·변경 요청: “시동 실패 화면에서 터치 좌표가 갱신되지 않아 복구 버튼이 반응하지 않습니다.”
- B의 캐시 잠금, C의 솔버 자동 감지, E의 화면 개선은 각 목적과 적용 의존성을 별도로 설명합니다.

## 2. 인용할 검증 근거

세 복구 경로 모두 실기 근거가 있지만, 시험 조건과 조작 방법은 서로 다릅니다. “모든 상태에서 모든 버튼을 검증했다”고 쓰지 않습니다.

| 경로 | 확인한 범위 | 제출 시 밝힐 제한 |
|---|---|---|
| 웹 7000 | A 단독의 손상 솔버·캐시 상황에서 접수된 재빌드 요청으로 복구했습니다. | 첫 클릭은 `GIT_BUSY`로 거절됐고 이후 접수된 클릭에서 복구했습니다. 합동 시험에는 화면 클릭 대신 같은 요청 경로를 호출한 시험도 있으므로 구분합니다. |
| 리커버리 6999 | 정상 상태에서 실제 `Tools → rebuild → Rebuild` 버튼으로 복구했습니다. 실제 컴파일 실패 상태에서는 사용자가 터미널 명령으로 복구했습니다. | 컴파일 실패 상태의 터미널 입력을 웹 버튼 클릭으로 기록하지 않습니다. |
| 본체 시동 실패 화면 | `626b887d`에 A+D 두 번째 수정본+E를 적용하고 생성 솔버 소스에 실제 컴파일 오류를 넣었습니다. 사용자가 짧게 한 번 누른 첫 시도에서 복구했습니다. | 성공 사례는 한 번이며, 터치 길이를 수치로 측정하지 않았습니다. 이전 A+D 첫 무응답의 원인은 미확정입니다. |

본체 시험의 핵심 근거는 [재부팅 후 남은 터치 기록](../analysis/2026-10-13-rebuild-ADE-screen/touch.jsonl)입니다.

- `(143, 207)`이 `rebuild`로 판정됐고 당시 상태는 바쁘지 않은 `failed`였습니다.
- `accepted=true`로 요청을 수락한 뒤 `cleaning` 상태가 기록됐습니다.
- 재부팅 함수를 호출하기 직전 `request_exists=true`가 기록됐습니다. **수락 기록과 이 기록 사이의 약 4밀리초를 실제 재부팅 소요 시간으로 해석하지 않습니다.**
- 캐시 파일 2,521개를 정리했고, 요청 관측부터 정상 기동 관측까지 약 416.9초, 즉 6분 57초가 걸렸습니다. 관측 간격의 지연을 포함합니다.
- 시험용 오류가 사라졌고 두 솔버 소스의 해시가 정상값과 일치했습니다. 두 솔버와 `plannerd` 불러오기, 기기 점검 다섯 항목이 통과했습니다.
- 원래 `carrot-wip-brh`의 `8399bb83`, 기존 수정·모델·캐시·설정을 복원했습니다. 복원 비교 일곱 항목과 기기 점검 다섯 항목이 통과했고 시험 백업과 전달 폴더를 삭제했습니다.

## 3. 클코 의견에 대한 판단

| 의견 | 제출 문서에 반영할 판단 |
|---|---|
| 이번 실제 복구에서 E의 아래쪽 확장은 쓰이지 않았습니다. | 동의합니다. `y=207`은 원래 버튼 범위 `188 ≤ y < 232` 안이며 작업 중 상태도 아니었습니다. 입력 갱신 문제의 근거는 앞선 비교 진단입니다. 이번 시험은 A+D+E 조합의 복구 성공으로 기록하고 D만의 독립 시험으로 바꾸어 쓰지 않습니다. 실제 정리와 복구에는 A도 필요합니다. |
| `_BACKEND` 대신 `touch.fd is not None`을 써도 같습니다. | 동의하지 않습니다. 전자는 실제로 로드된 백엔드이고 후자는 원시 터치 장치의 열기 성공 여부입니다. 기기용 백엔드에서도 장치 열기가 실패하거나 도중에 닫히면 마우스 입력 대체 경로를 사용합니다. 이때 `touch.fd` 조건은 필요한 명시적 입력 갱신을 생략할 수 있습니다. 비공개 이름 의존은 검토 쟁점으로 인정하되, 현재 검증본의 조건을 유지하는 편을 권합니다. |
| D의 원인 수정과 진단 기록을 구분해야 합니다. | 동의합니다. 본문에서 입력 갱신 수정과 기록 기능을 별도 항목으로 설명합니다. 기록은 이전 시험에서 좌표가 재부팅과 함께 사라진 문제를 보완합니다. 상류가 최소 수정을 원하면 기록 기능 분리를 논의할 수 있지만 이번에는 패치를 나누거나 수정하지 않습니다. |
| D와 E에도 시험 코드를 포함해야 합니다. | 동의합니다. 보존된 로컬 검증 8개는 현재 패치에 포함되지 않았습니다. 제출 구성의 보완 항목으로 명시하고, 현재는 시험 파일과 실행 결과를 근거로 연결합니다. 패치에 시험 코드까지 들어 있다고 주장하지 않습니다. |
| E는 표시 크기도 바꾸고 안내가 한국어뿐입니다. | 동의합니다. 시험 기기의 `536×240` 배치에서 버튼 높이가 44에서 52픽셀로 늘어 표시와 판정이 함께 바뀝니다. 안내도 한국어만 추가됐습니다. 판정 영역만 늘릴지와 두 언어 안내 여부는 후속 설계 선택으로 남기고 이번에는 바꾸지 않습니다. |
| 최신 상류 기준으로 패치 이름과 기준을 통일해야 합니다. | 제출 구성상 타당합니다. 다만 `b98d5053`이 당시 최신이고 A·D·E가 적용된다는 내용은 클코의 보고입니다. 이번 작업에서 원출력이나 원격 상태를 재확인하지 않았습니다. 보존된 실기 근거의 기준은 `626b887d`이며, 새 기준에서 실기 검증한 것으로 쓰지 않습니다. |

## 4. 적용 관계와 제출 구성

| 묶음 | 설명할 순서와 범위 |
|---|---|
| A → B → C | 버튼 요청 복구, 공통 캐시 잠금, 솔버 자동 감지 순서입니다. 배포용 C는 B의 보호 아래에 두는 구성입니다. A 단독에는 동시 실행 보호가 없습니다. |
| A → D 두 번째 수정본 → E | 본체 버튼을 통한 실제 복구 시험의 구성입니다. 현재 E 패치는 D 두 번째 수정본의 변경 줄에 의존합니다. D의 입력 갱신 문제 자체는 A 이전 화면에도 있던 별도 문제입니다. |

현재 `docs/`의 A·B·C 원본 이름은 `910bd82f`, 새 D·E 이름은 `626b887d`를 포함합니다. 파일 이름만 통일하여 같은 기준에서 검증한 것처럼 보이게 하지 않습니다. 제출 기준을 정할 때 패치 기준과 적용 확인, 실기 시험 기준을 각각 명시해야 합니다. 이번에는 재생성하지 않습니다.

제출 본문은 문제와 변경 동작, 위 검증 표, 남은 한계 순서로 짧게 구성하고 원출력 링크를 붙이는 편을 권합니다. 기존 초안에는 과거 시점의 “미검증” 문장과 후속 정정이 함께 있으므로, 제출할 때는 이 문서의 최신 범위를 사용하고 전체 작업 이력을 그대로 붙이지 않습니다.

## 5. 6999 터미널 안내에 남길 한 줄

패치 A 또는 같은 재빌드 요청 처리 기능이 적용된 런처가 있는 기기에서 사용한 명령입니다.

```bash
touch /data/rebuild_all.request && sync && sudo reboot
```

요청을 저장하고 즉시 재부팅하며 다음 부팅에서 생성물과 캐시를 정리합니다. 요청을 처리하지 않는 버전에서는 같은 효과를 보장하지 않습니다. 추적 원본 소스 자체의 컴파일 오류를 수정하는 명령도 아닙니다. 이 명령은 보존할 사용자 안내이며 이번 문서 작업에서 실행하지 않았습니다.

## 6. 남겨야 할 한계와 이번 종료 범위

이전 A+D 첫 무응답, 의도보다 접촉이 한 번 더 잡힌 현상의 원인, 짧은 터치의 성공률은 미확정입니다. E의 경계 확장과 작업 중 안내는 별도 진단 및 로컬 코드 검증의 결과이며 실제 복구 성공 좌표는 원래 버튼 영역 안이었습니다. 전원 차단 중 복구와 전체 복구 단계의 재시도 제한도 이번 근거로 해결됐다고 주장하지 않습니다.

추가 시험과 코드 변경은 하지 않습니다. `_BACKEND` 조건 교체, 기록 기능 분리, 시험 코드의 패치 편입, E의 표시·언어 변경, 새 기준으로 패치 재생성은 모두 실행하지 않은 제출 검토 항목입니다. 이슈와 풀 리퀘스트도 게시하지 않습니다.
