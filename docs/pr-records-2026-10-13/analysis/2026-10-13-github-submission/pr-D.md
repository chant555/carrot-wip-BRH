# [carrot-wip] 당근 실행 실패 화면의 터치 입력을 갱신하고 판정 기록을 보존합니다

관련 이슈: #546

기기용 raylib 백엔드에서 입력 좌표가 갱신되지 않아 복구 버튼이 반응하지 않는 문제를 수정합니다.

관련 변경 요청은 Rebuild All 복구 #541과 캐시 잠금 #542입니다. 이번 요청에는 D의 두 파일만 포함합니다.

## 변경 내용

- 실제로 로드된 `COMMA` 백엔드에서 `poll_input_events()`를 호출합니다. 일반 컴퓨터용 백엔드는 이미 화면 그리기 종료 시 입력을 갱신하므로 추가 호출하지 않습니다.
- `_BACKEND`는 비공개 이름이므로 의존성 검토가 필요합니다. 원시 터치 장치 열기 성공 여부는 백엔드와 다른 상태이므로 `touch.fd` 조건으로 대체하지 않습니다.
- 터치 좌표·판정·요청 수락과 재부팅 직전 상태를 파일에 기록합니다. 앞선 시험에서 재부팅과 함께 좌표 근거가 사라졌던 문제를 보완합니다.
- 약 256키비바이트 기준으로 현재 기록과 이전 기록을 순환 보존합니다. 마지막 기록만큼 기준을 넘을 수 있으며, 기록 실패가 복구를 막지 않도록 합니다.

## 검증과 범위

- comma 4의 비교 진단에서 입력 갱신 전 누름 네 번은 모두 `(0, 0)`이었고, 갱신 후 버튼 판정이 회복됐습니다.
- `626b887d`의 A+D+E 실제 복구 시험에서 사용자가 짧게 한 번 누른 첫 시도로 복구했습니다. 좌표 `(143, 207)`과 요청 수락 기록이 재부팅 후에도 남았고 약 6분 57초 뒤 정상 기동했습니다.
- 성공 좌표는 원래 버튼 영역 안이었습니다. E의 아래쪽 확장과 안내 효과는 별도 진단·로컬 검증으로 구분합니다. D·E 관련 로컬 검증 8개는 현재 패치에 포함되지 않았습니다.
- 이전 첫 무응답과 추가 접촉의 원인은 미확정입니다. 짧은 터치의 성공률이나 C3x 동작을 입증한 것은 아닙니다. 공통 입력 백엔드 수정이므로 기종 고유 특성에 대한 의존은 비교적 적다고 판단합니다.

비교 진단과 본체 복구 기록을 근거로 합니다. 이번 제출용 사본은 주석·모듈 설명만 정리했으며 추가 시험은 하지 않았습니다.

## 제출 기준과 검토 상태

- 대상은 `ajouatom/openpilot:carrot-wip`이며 제출 기준은 `b98d5053`입니다. 기존 실기 검증은 `626b887d`에서 수행했습니다.
- 현재 기준에서 패치 적용만 확인했습니다. 추가 실행·기기 시험은 하지 않았으며 검토용 초안으로 제출합니다.
- C3x에서는 시험하지 않았습니다. C와 E는 이번 변경 요청에 포함하지 않았습니다.
- 실제 복구 성공 기록은 A+D+E 조합의 결과입니다. 이 변경 요청에는 D만 포함하며, 입력 갱신 전후 비교 진단과 구분해 검토해 주십시오.

```text
press: (143, 207), hit=rebuild, state=failed
action: accepted=true, state=cleaning
reboot 직전: request_exists=true
캐시 파일 2,521개 정리 → 416.9초 후 정상 기동 관측
```
