# 초기 감속 보정의 제어 계산 내부 통합 기록

작성일은 2026-11-08입니다. `carrot-wip-brh`의 `8dd0723d22a34bc6ded9ef66e4183ab83f10e106`에서 `carrot-wip-brh-decel`을 만들었습니다. 사용자는 실제 제어 계산 내부 통합과 검증까지 승인했고, 기기 적용은 별도로 진행하기로 했습니다. 기존 두 브랜치는 이동하지 않았습니다.

## 적용한 동작

접근속도와 현재·1초 후 예상 거리 부족을 함께 사용해 앞차의 감속 초기에 짧은 추가 감속을 요청합니다. MPC(모델 예측 제어) 계산 안에 가속도 상한 선호를 한쪽 방향의 완화 제약으로 추가했습니다. 속도·가속도·가속도 변화율을 같은 궤적에서 계산하며, 이번 기능이 계획기 출력 뒤에서 목표 가속도를 덮어쓰지 않습니다. 기존 선행 감속 출력 보정은 기존 코드 그대로입니다.

- 앞차보다 0.15~0.60m/s² 더 감속하는 가속도 기준을 만들고, 접근속도와 거리 부족에 따라 강도를 조절합니다. 실제 차량 가속도가 반드시 그 값에 도달하도록 강제하지 않습니다.
- 초기 구간의 최대 길이는 1.8초이며, 제약의 가중치는 0.8초에 걸쳐 증가합니다. 앞차가 다시 가속하거나 접근·거리 부족이 해소되면 더 일찍 완화합니다. 앞선 출력 보정 사본의 1.5초에서 내부 계산의 전환 특성에 맞춰 조정했습니다.
- 초기 구간 이후에는 추가 감속 요청을 완만하게 해제합니다. 후반에 앞차 감속을 강제로 계속 추종하거나 차간거리를 고정하지 않습니다.
- 같은 연속 감속에서 반복해서 초기 보정을 재발동하지 않습니다. 앞차의 감속 종료·접근 해소 조건이 0.5초 유지돼야 다음 감속에 다시 준비합니다.
- 기존 가감속 한계, 앞차 장애물, 위험 거리 제약, 추종 시간과 차간 여유 계산을 유지합니다. 더 강한 기존 감속에는 추가 벌점을 주지 않습니다. `TFollowDecelBoost`와 기기 설정도 변경하지 않았습니다.
- 신뢰할 수 있는 같은 레이더 추적이 3회 이상 유지돼야 사용합니다. 메시지가 0.15초보다 오래됐거나 입력이 무효이면 해제합니다. 제어 초기화, 정차 유지, 페달 개입, 강제 감속, 차선 변경, `blended` 모드에서는 추가 보정을 끕니다. 저속에서는 2~5m/s 사이에서 효과를 완화합니다.

약 9m는 첫 사례의 비교 목표입니다. 코드에 모든 상황의 고정 목표 거리나 최소 보장 거리로 넣지 않았습니다.

## 검증 범위와 수정 과정

최종본은 7개 재현 조건·반복 감속 8주기·예외 조건 11종에서 계획기를 31,921회 호출했고, 내부 재계산을 포함해 실제 계산은 31,926회였습니다. 최종 묶음의 외부 계산 상태와 QP(이차 계획법) 내부 상태가 모두 정상(0)이었습니다. 통합안의 위치·속도·가속도·가속도 변화율이 같은 운동 방정식에 맞는지도 각 호출에서 확인했습니다. 비활성 비교의 최대 거리 차이는 0.00002357m, 목표 가속도 차이는 0.00000619m/s²였습니다.

최초 내부 통합에서는 물리 가속도 상한을 직접 제한해 명령 변화율이 과도했습니다. 이를 별도의 완화 제약으로 분리하고 진입을 평활화했습니다. 이어 초기 상태와 입력이 급변하는 검사에서 기존 반복 한도 10회로는 내부 계산이 덜 수렴함을 확인했습니다. 외부 반환값만 정상인 경우에도 궤적 오차가 커질 수 있어 내부 상태와 궤적 검사까지 추가했습니다. 최소 제약 가중치를 주는 시도와 빌드 옵션 일치는 이를 해결하지 못했습니다. 최종 반복 한도를 20회로 늘린 뒤 해당 초기화는 최대 16회, `blended` 모드는 최대 13회에 정상 수렴했습니다. 다른 조건의 최대 반복 수를 포함한 최종 기록은 분석 폴더에 보존했습니다.

C4의 임시 폴더에서 새 계산기를 생성·빌드했습니다. 계산기 내부 소요 시간의 99백분위는 기준 1.13ms, 통합안 1.41ms였습니다. 이는 정차 중 단독 재현의 계산기 시간이며 주행 중 전체 계획기 부하 검증은 아닙니다.
