# 2026-09-26 C4 주행 분석

> 2026-09-28 공개 보관본. 본문의 현재/미설치 표현은 각 분석 시점 기준이다. 같은 날 후속 업데이트와 도구 보완 결과는 [README](README.md) 및 [인계 요약](HANDOFF.md)을 참고한다.

## 결론

두 주행의 비어 있지 않은 원본 rlog 55개, 총 4,582,795개 메시지를 분석했다. Panda registerDivergent를 포함한 결함은 전체 기록에서 0건이다. 시작 15초 이후의 카메라·모델·자세 추정·차량 CAN·레이더 유효성 검사에서는 이상이 발견되지 않았다. SPI 체크섬 누적 증가와 GPS 위치 미확정/궤도 정보 저장 실패는 별도 추적할 항목이다.

## 범위와 방법

- 차종: HYUNDAI_IONIQ_5_PE / C4(cuatro Panda).
- 두 주행 initData 커밋: 9dc61d3a88ad5999ad7a916853c06932005caea3, happymaj11r/carrot-wip-model_selector, AGNOS 19.8-carrot-bt1.
- NAS 로그 조회 실패 후 /data/media/0/realdata 원본을 읽기 전용으로 분석했다.
- 전체 openpilot.cereal.log 스키마와 zstandard로 해독했다. qlog는 경고·온도·속도·상태 집계, rlog는 프레임·모델·자세·CAN 정밀 검사에 사용했다.
- 시작 후 15초를 초기화 구간으로 분리했다. 아래 안정 구간 결과를 초기화까지 포함한 무오류 주장으로 해석하면 안 된다.
- 시간은 clocks.wallTimeNanos와 단조 시계의 대응으로 KST 변환했다. 오전 initData의 wallTime은 시간 동기화 전 값이어서 직접 사용하지 않았다.
- 거리는 qlog vEgo의 사다리꼴 적분에 따른 근사치다. 제어 활성 시간은 시작 15초 이후 100 Hz carControl 샘플 수 기반 근사치다.

## 남은 관찰 항목

### 1. SPI 체크섬 누적 증가

- 오전 1→49(+48), 저녁 1→25(+24). Panda 결함과 별도의 통신 진단 카운터다.
- CAN 수신 유효성이나 안전 RX/TX 차단, heartbeat 끊김, 모델/자세 오류를 동반한 증거는 없다. 그렇다고 원인이 해결되었다는 뜻은 아니다.
- SPI 구현에 재시도 경로가 있으나, 이 분석만으로 모든 증가를 특정 재시도나 하드웨어 원인에 귀속할 수 없다.
- 오전 증가 군집: 10:43:03–04(+26), 11:03:38–39(+8), 11:04:36(+14).
- 저녁 증가 군집: 18:40:26(+14), 19:00:35–36(+10). 첫 군집은 주행 중이고 나머지는 정지 상태였다.
- 저녁 CAN bus1 totalErrorCnt는 첫 값 1에서 마지막까지 1로 고정. 두 주행 bus1 canCoreResetCnt도 1로 고정되어 주행 중 추가 증가가 아니다.

### 2. GPS 위치 미확정과 궤도 정보 저장 실패

- 각 주행 약 5분마다 Received NACK from ublox / Error storing almanac가 한 쌍으로 발생, 각각 5회(합계 10회 저장 실패).
- 코드는 위성 궤도 정보의 GPS 장치 플래시 백업 명령에 대한 실패를 기록한다. 실시간 위치 수신 실패와는 구분해야 한다.
- 초기 위치 확정 지연과 백업 실패의 인과관계, 터널/지하주차장 등 환경 원인은 확인하지 않았다.
- 아래 위치 미확정 구간은 qlog hasFix 기반이며 약 1초 수준으로 해석한다. 마지막 미확정 구간은 기록 종료까지 이어져 실제 회복 시각을 알 수 없다.

### 3. 시작 시 초기화 오류

- 시작 약 0.2–0.7초에 카메라 ioctl 오류(errno 19)가 카메라별로 기록된다. 이후 세 스트림이 정상 생성되며 정상 주행 구간에 같은 오류가 재발하지 않았다. 이 코드만으로 카메라 하드웨어 고장이라고 판단하지 않는다.
- 모델 시작 약 3–7초에 프레임 이력 건너뜀: 오전 43/50/17, 저녁 44/50/17 프레임.
- selfdrived 초기화 대기 6.01초 타임아웃과 radarFault/locationdTemporaryError/commIssue 계열 이벤트가 시작 약 7–8초에 있었다. 이때 enabled=False이며 차량은 사실상 정지 상태였다.
- 이후 최초 이동은 오전 10:40:33, 저녁 18:38:44. 최초 selfdriveState.enabled=True는 10:43:01, 18:40:24였다.
- 주행 중 고장에 의한 softDisable/immediateDisable 이벤트는 추가로 발견되지 않았다. 초기화 로그를 이미 체결된 주행의 강제 해제로 해석하지 않는다.
- 시작 부근 athenad WebSocket 연결 종료도 기록되며 차량 제어 오류와 구분한다.

## 감속 및 종료

- 오전 10:49:23–26 부근 약 -4.18 m/s²의 감속이 있었다. qlog의 -3 m/s² 미만 30개 표본 모두 brakePressed=True, longActive=False였다. 해당 구간은 자동 가감속 명령에 의한 급제동으로 볼 근거가 없다.
- 자동 가감속이 활성화된 전체 원본 표본에서 요청 가속도 최솟값은 두 주행 모두 -2.0 m/s²였다.
- 두 주행 마지막 carState는 속도 0, P단, standstill=True다.
- 오전 --29의 rlog/qlog는 0바이트와 lock 파일만 존재한다. --0~28은 해독 오류 없이 읽혔다. 다음 세그먼트 개설 시 종료된 흔적일 수 있으나 종료 원인은 단정하지 않는다.

## 한계 및 다음 확인

- 영상과 도로 상황을 대조한 차선 유지 품질·승차감·특정 선행차 선정의 정답 검증은 수행하지 않았다. 오류 카운터가 없다는 사실만으로 모든 제어 판단이 옳았다고 결론 내리지 않는다.
- 경고음 청취·마이크 녹음 검증은 하지 않았다. 다만 실제 두 주행 모두 Panda registerDivergent가 재발하지 않았다는 점은 확인했다.
- 우선 추적 항목은 SPI 오류 군집의 재현 조건, GPS 초기 위치 확정과 almanac 백업 실패다. 이번 작업에서는 설정·소스·펌웨어·브랜치를 변경하거나 재부팅하지 않았다.
