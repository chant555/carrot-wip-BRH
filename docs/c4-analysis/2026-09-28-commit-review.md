## 판단 요약

85개가 모두 새로운 주행 제어 수정은 아니다. 별도 Jetlink/Jetson 개발 이력, 설치 도구와 검증 문서가 대거 통합되었다. 사용자의 C4에는 레이더 오인식 억제와 순정 HUD 표시 수정이 관련 있고, 정지 판단 하한은 현재 설정이 이미 10이어서 정상 저장값 기준 변화가 없다. C3 화면 CPU 배치 변경도 C4에는 적용되지 않는다.

다만 Jetson 미연결 상태에서도 새 jetlinkd 서비스와 upstream modeld의 어댑터 초기화·상태 확인이 추가된다. 따라서 전체를 문서·설치 도구 변경으로만 보거나 기존 C4 실행 성능이 완전히 같다고 단정할 수 없다. 새 코드의 이 차량 주행 결과는 아직 없다.

## 1. 정지 판단 최저값 보정

대표 커밋: `e16aba26`, 모델 선택 엔진 보완 `df1f46a8`.

정지출발민감도 VEgoStopping의 설정 최저값을 1에서 10으로 올린다. 10은 계획 속도 기준 0.10 m/s다. 저장값이 10보다 낮으면 시작 시 10으로 보정하고, 실행 중에도 같은 하한을 적용한다. 비수치·무한 값은 기본값 50으로 복구한다. 정상 범위 값, 기본값 50, 상한 100은 유지한다.

배경은 다른 Ioniq 5의 VEgoStopping=2 기록이다. 계획 속도가 지나치게 낮은 문턱을 통과하지 못해 정지 요청이 늦어졌고, 그 사이 앞바퀴 후진 방향이 반복 검출됐다. 같은 기록에 10을 대입하면 정지 판단 시점이 앞당겨지지만 실제 수정 차량의 밀림 해결을 입증한 주행은 아니다. 정지 감속값과 재시도 상태기계는 변경하지 않는다.

**이 C4는 이미 10이다. 따라서 이번 하한 보정만으로 정지·출발 성격이 달라질 것으로 보지는 않는다.** 예전 안내의 5 권장은 삭제되었다. BRH와 별개인 레거시 모델 엔진에도 동일한 하한 처리를 넣어 planner와 model의 정지 판단 불일치를 막았다.

## 2. 레이더 미확정 물체의 선행차 승격 제한

대표 커밋: `51065492`.

영상의 선행차 근거 없이 전방 레이더만으로 움직이는 선행차를 선택할 때, 레이더 자체 상태가 tentative(1)인 후보를 제외한다. 종전에는 0.75초 유지되면 이런 후보도 채택될 수 있었다. 미확정 후보가 기존 선행차를 밀어내거나 계속 선행차로 남는 경로도 제한된다.

배경인 EV9 기록에서는 영상상 대응 차량이 확인되지 않는 물체가 한 프레임 L1으로 선택됐고, planner는 -2.04 m/s²를 요청했다. 수정한 기록 재생에서는 그 선택이 사라졌다. 이는 모든 급감속 해결이나 실차 제동 성능 검증을 뜻하지 않는다.

- 영상과 매칭하는 경로는 유지한다.
- 상태 정보가 없는 0, 확인된 2·3은 기존 호환성을 유지한다.
- 실제 차량이어도 계속 상태 1이고 영상 근거가 없으면 이 레이더 단독 경로에서는 선택하지 않는다. 오인식 억제와 함께 봐야 할 기능상 제약이다.
- 개발자 문서상 903개 레이더 관련 시험과 254개 종방향 시험이 통과했다. 기존 98개 로그의 판정은 유지되었으나 원래 실패·미검증 항목이 남아 있어 모든 과거 사례가 통과했다는 뜻은 아니다.

**현재 레이더 모드 1인 이 C4에 관련 있는 주행 제어 변경이다.** 이전 사용자 주행에서 같은 오인식이 있었다고 확인한 것은 아니다.

## 3. 순정 계기판·HUD 선행차 색상 깜빡임

대표 커밋: `3e838797`.

Hyundai CAN FD의 선행차 색상을 회색으로 바꾸는 상대속도 기준이 0 초과에서 +0.3 m/s 초과로 바뀐다. 정차 중 레이더 상대속도가 0 부근에서 흔들릴 때 흰색·회색이 반복되는 현상을 줄이려는 수정이다. 무효·없는 선행차는 기존처럼 표시를 지운다.

변경은 순정 화면용 표시 필드다. 선행차 거리, 송신 상대속도, 가속·감속 명령을 바꾸지 않는다. +0.3 경계에서 값이 흔들리는 상황까지 막는 히스테리시스는 아니다. 개발자 측 62개 관련 시험 통과 기록이 있으며 실차 화면 확인은 별도다.

## 4. Jetson 외부 추론·USB 계기판 통합

85개 이력 중 큰 비중을 차지한다. 주요 기능은 다음과 같다.

- Jetson의 외부 모델 추론, 늦은 부팅 후 연결, 분리·재부팅 복귀 처리.
- USB 계기판과 내비 영상 전달, 영상 조각 잘림·수신 정체·과도한 대기 반복 개선.
- Jetson/Mac 호스트 구분과 연결 상태·온도·IP 등 표시.
- 호환되는 서명 업데이트 지정, 저장된 Wi-Fi 정보의 USB 전달.
- 한국어·영어 Windows 설치 도구, SD 기록·검증·첫 부팅 준비.
- 후반 커밋은 전원 중단 시 저장장치·업데이트 복구와 Wi-Fi 복구를 위한 새 이미지 후보 및 검증 도구.

실행 관계는 내부 모델 / 기존 eGPU Cinque v3 / Jetson 고정 Cinque v2로 구분된다. 현재 BRH 내부 모델 선택이 업데이트만으로 Cinque v2로 바뀌는 것은 아니다. 그러나 Jetson을 실제 연결하고 전환 조건이 충족되면 외부 추론은 고정 Cinque v2를 사용한다. BRH를 외부 장치로 그대로 옮겨 실행하는 기능으로 이해하면 안 된다.

upstream_default와 upstream_custom 경로에는 JoiningModel 어댑터가 적용된다. 이 C4의 BRH supercombo는 upstream_custom 경로다. 레거시 모델 엔진에는 구조·출력 계약 차이 때문에 Jetlink 어댑터를 이식하지 않았다.

코드상 내부 모델이 먼저 최소 3번 결과를 낸 후 외부 전환을 허용한다. 상태가 신선하고 유효해야 하며, 정차 또는 물리적 조향 개입 조건을 확인한다. 활성 외부 추론이 실패하면 commIssue를 알리고 내부 모델로 복귀한다. 무중단 제어를 보증하는 전환은 아니다.

**미연결 C4에도 남는 변경:** jetlinkd가 대기하고, modeld가 어댑터를 준비하며 주기적으로 상태를 확인한다. C4의 운전자 감시에는 업로드 시점 동기화 보조 경로가 추가된다. 신선한 외부 업로드 신호가 없으면 해당 대기는 즉시 반환하도록 되어 있다. 코드 의도와 실제 지연·부하가 같은지는 업데이트 후 측정해야 한다.

검증 기록은 넓지만 범위를 구분해야 한다. 기존 C4 정차 시험, Windows 시험, 통합 Linux 빌드·회귀 성공이 통합된 최신 코드의 이 차량 실주행 검증을 대신하지 않는다. 특히 최신 addd48d9 문서는 보호 저장장치 이미지 후보의 실물 SD 부팅과 공개 배포가 아직 남았다고 명시한다. 기존 공개 설치 도구까지 모두 미검증이라는 뜻은 아니다.

## 5. C3/C3X 화면 처리와 내비 연결 보호

`a312abbe`: C3/C3X의 주행 중 UI를 core6만이 아니라 작은 코어 0~3에서도 실행할 수 있게 한다. 낮은 우선순위 nice19는 유지한다. **C4는 기존 core6 배치를 유지**하므로 사용자 C4의 과거 광각 카메라 95.44 ms 사건을 해결하는 변경으로 볼 근거가 없다.

내비 수신 코드에는 다른 휴대전화가 연결을 시도할 때 기존 휴대전화의 정상 세션을 무효화하지 않도록 소유 연결을 관리하는 변경도 포함된다. 현재 연결을 유지하고 두 번째 연결에 사용 중임을 알린다. 이것은 Jetson 설치 도구에만 국한된 수정이 아니다.

## 6. Git LFS에서 일반 Git으로 파일 저장 전환

대표 커밋: `c90d6e38`.

모델·업데이터 등 7개 파일을 LFS 포인터 대신 일반 Git 파일로 보관한다. LFS 대역폭 소진에 따른 배포 문제를 줄이는 목적이다. 개발자 기록상 7개 모두 원래 크기·SHA-256이 같으며, 이 변경으로 모델 내용·모델 선택·AGNOS 요구 버전이 바뀌지는 않는다.

큰 모델 파일이 변경 목록에 나타나거나 변경 줄 수가 매우 커도 새 학습 모델이라는 뜻은 아니다. NAS에서 받는 외부 모델 경로는 유지된다. 예전 커밋 이력은 재작성하지 않았으므로 과거 버전 접근은 여전히 LFS에 의존할 수 있다.
