## 주요 관측과 한계

- 이전 두 커밋의 분석 표본에서 `registerDivergent`를 포함한 Panda 결함은 관측되지 않았다. 향후 재발 부재나 전체 주행 안전성을 보증하지 않는다.
- SPI 카운터 증가 빈도는 후속 표본에서 낮았지만 조건을 통제한 비교가 아니며 코드 수정 효과로 단정하지 않는다.
- 광각 카메라 약 95.44 ms 간격 및 모델 입력 누락 사건 1개를 확인했다. GPS almanac 저장 실패도 계속 관측했다.
- 업데이트 후 빌드·BRH 컴파일 스탬프와 오프로드 서비스는 확인했다. Jetlink `waiting`은 짧은 관찰 구간의 결과다.
- 구 도구의 정지 6개 장면을 자동 정지 검증 완료로 보지 않는다. 보완 도구로 재검사한 ea 주행은 조건 충족 1개/제외 5개이며, 마지막 qlog 손상 때문에 전체 결과는 부분 분석이다.

## 실행

점검 도구는 [tools/c4check](../../tools/c4check/)에 있다. PC의 SSH 별칭 `c4`가 자신의 장치를 가리키도록 준비한다. 로그 분석에는 대상 CarrotPilot 버전의 전체 cereal 스키마와 Python 의존성이 필요하다. 임의의 openpilot 버전과의 호환성은 검증하지 않았다.

저장소 루트에서:

```bash
python3 -m unittest discover -s tools/c4check/tests -v
bash tools/c4check/boot.sh
bash tools/c4check/drives.sh ROUTE--ID
```

`ROUTE--ID`를 실제 주행 이름으로 바꾼다. 묶음은 `/tmp/chk`에 도구 사본을 전송하여 관측한다. Pull·재부팅·차량 설정 변경은 수행하지 않는다. 종료코드 0은 요청 범위 분석 완료, 1은 확인할 관측 항목, 2는 자료 부족·손상 등 부분 분석이다. 자세한 제약은 사용법을 따른다.

## 공개 범위

최근 보고서 4개, 보완 도구·검사, 사용법, 이 인계 요약을 포함한다. 원본 C4_500의 전체 HANDOFF/index와 과거 조사 자료를 통째로 올린 것은 아니다. 원본 주행 로그, 영상, 설정 덤프, 인증정보, 장치 고유번호, 전체 주행 식별자, 개인 PC/NAS 경로는 포함하지 않는다. e6~eb는 보고서 내 주행 구분용 별칭이다.

원본 로그와 상세 집계·손상 증거는 사용자 로컬 비공개 보관 자료다. 공개본만으로 모든 실차 수치를 독립 재현할 수 없으며, 포함된 합성 회귀 검사는 실제 주행 검증을 대신하지 않는다.
