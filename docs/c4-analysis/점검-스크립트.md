## 실행과 종료코드

PC 저장소 루트에서 실행한다. 먼저 자신의 장치에 접속하는 SSH 별칭 `c4`를 설정하고 인증을 확인한다. 아래 `ROUTE--ID`는 실제 장치 로그의 주행 이름으로 바꾼다:

```bash
bash tools/c4check/boot.sh
bash tools/c4check/drives.sh ROUTE--ID
```

`drives.sh`에서 route를 생략하면 qlog 수정 시각 순 최근 4개를 선택한다. 부팅 시계 보정으로 수정 시각 순서도 어긋날 수 있으므로 정확한 비교에는 route를 명시한다. 전송 파일은 읽기 전용 점검 도구이며 Pull·재부팅·차량 설정 변경을 하지 않는다.

각 Python 도구는 JSON을 출력한다. 묶음은 도구 이름과 각 JSON을 차례로 출력한다. 전체 결과는 단일 JSON 문서가 아니다.

| 종료코드 | 뜻 | 해석 |
|---|---|---|
| 0 | 요청 범위 분석 완료, 해당 검사의 확인 항목 없음 | 자동 정지 성공이나 전체 시스템 정상 인증이 아님 |
| 1 | 오류·카운터 증가 등 확인 항목 관측 | 부팅 초기화·일시적인 경고와 실제 고장을 사람이 구분 |
| 2 | 입력 없음·누락·손상·실시간 메시지 부재 등 | 읽은 부분은 출력하지만 완전한 판정은 불가 |
| 그 밖의 비영(SSH 등) | 접속·전송·실행 실패 | 분석 성공으로 해석하지 않음 |

묶음은 한 검사에서 1·2가 나와도 다음 검사를 계속하고 가장 큰 상태를 반환한다. 경고·표준오류를 필터로 숨기지 않는다. 프로그램 예외도 비영 코드로 전달한다. 누락 값은 0 대신 `null`, 자료 부족은 `incomplete`로 표시한다.

## 도구별 범위

| 도구 | 검사 내용과 한계 |
|---|---|
| `boot.sh` | `buildcheck`, `bootcheck`, `mstate`, `pandafaults`, `jetlink`를 순서대로 실행 |
| `buildcheck.py` | SCons 완료 로그, 두 MPC 솔버 실제 import, 현재 코드와 BRH 컴파일 스탬프 일치, 실패 표시, HTTP 7000/6999 응답. 실제 추론은 별도 |
| `bootcheck.py` | mtime으로 선택한 swaglog 후보의 ERROR/crash/Jetlink와 JSON 손상. 시간 보정 전 닫힌 파일 누락·이전 부팅 혼입 가능성을 출력 |
| `mstate.py` | 기본 5초간 manager/device 수신·alive·valid 및 실행 예상 프로세스 확인. 미수신을 정상으로 취급하지 않음 |
| `pandafaults.py` | 기본 5초간 Panda 결함, heartbeat, 안전 검사, SPI/CAN 누적 카운터 변화. 점화·device.started와 noOutput을 함께 표시 |
| `jetlink.py` | 기본 5초간 상태 파일 신선도·상태 변화·USB 역할 관찰. 과거 주행 이력은 아님 |
| `drives.sh` | 지정 주행의 `drive.py`와 `stops.py` 실행 |
| `drive.py` | 전체 qlog의 입력 범위, 커밋, 서비스 표본 수, 오류, Panda/SPI/CAN, pose 유효성, 모델 시간·drop 지표, Jetlink 로그 예시 |
| `stops.py` | 최근 12초의 자동 가감속·페달·선행차·결합 시각 조건으로 정지 후보 분류. 제외 이유도 출력. 정지 후 유지·후진은 검사하지 않음 |
| `counters.py` | 선택한 rlog 구간의 MDPS/TCS RX/TX 카운터. 불연속 세그먼트/시간 경계에서는 비교하지 않음. CRC·실제 버스 송신 확인은 별도 |
| `cpu.py` | 프로세스 CPU 누적 증분을 공통 관측 시간으로 나눈 평균 및 온도. 짧게 실행된 프로세스를 전 구간 부하처럼 더하지 않음 |
| `tl.py` | 특정 시간대 qlog의 가감속·앞차·페달·longActive 및 결합 자료 신선도 |
| `checklib.py` / `remote.sh` | 공통 판독·범위·종료코드 / 원격 환경·결과 집계 지원 |

## 정지 후보와 카운터 판정

`stops.py`는 최근 12초 안에 3 m/s를 초과한 이동이 있고 0.1 m/s 미만으로 내려온 장면을 찾는다. 관측 접근 구간 전체에서 다음을 요구한다.

- `enabled` 및 `longActive`가 켜짐.
- 운전자 브레이크·가속 페달 개입 없음.
- 선행차 존재.
- carState와 결합하는 selfdriveState/carControl/radarState가 유효하고 0.5초 이내.
- carState 관측 시간에 0.5초 초과 공백이나 역행 없음.

0.5초와 12초는 **오프라인 후보 분류 기준**이다. 차량 제어 설정을 바꾸는 값이 아니다. 엄격한 기준 때문에 실제 정상 정지도 제외될 수 있다. 후보 0개와 고장 0개를 같은 뜻으로 읽지 않는다. qlog 사이의 미관측 개입이나 앞차 ID 교체, 정지 후 밀림은 이 검사로 배제할 수 없다.

카운터는 DBC에 기록된 비트 폭으로 순환 차이를 계산한다. 선택 구간을 정렬·중복 제거하고, 비연속 세그먼트나 기본 0.1초 초과 간격은 `uncompared_boundaries`로 센다. 단절을 넘는 점프를 코드 오류로 세지 않는다. 연속 구간의 +1 이외 값도 기록 손실·프로세스 재시작 등과 대조해야 한다. `sendcan`은 송신 요청이며 수신 echo나 CRC 검증 결과가 아니다.

## 장치에서 개별 실행

묶음을 실행하면 필요한 Python 파일과 원격 실행기가 업로드된다. 직접 준비할 때는 대상 폴더부터 만든다.

```bash
ssh c4 'mkdir -p /tmp/chk'
scp tools/c4check/*.py tools/c4check/remote.sh c4:/tmp/chk/
```

로그 분석은 C4 `/data/openpilot`에서 venv와 pydeps를 명시한다.

```bash
cd /data/openpilot
env PYTHONPATH=/data/openpilot/pydeps:/data/openpilot /usr/local/venv/bin/python3 /tmp/chk/counters.py ROUTE--ID 10
env PYTHONPATH=/data/openpilot/pydeps:/data/openpilot /usr/local/venv/bin/python3 /tmp/chk/cpu.py ROUTE--ID 10
env PYTHONPATH=/data/openpilot/pydeps:/data/openpilot /usr/local/venv/bin/python3 /tmp/chk/tl.py ROUTE--ID 790 5
```

로그 도구는 `--root`로 파일 위치를 지정할 수 있다. 실시간 메시지 도구는 환경 차이로 import가 실패할 수 있어 `boot.sh`가 manager의 실행 환경을 사용한다. 실시간 도구의 `--seconds`는 1~60초다. 정상 운용 중인 차량 서비스를 재시작하거나 강제 주행 모드로 바꾸지 않는다.

## 로그를 읽을 때

- 세그먼트 안에서는 메시지를 단조 시각 순으로 정렬해 기록 순서 차이에 따른 미래 상태 결합을 피한다. 세그먼트 사이의 단절은 별도로 다룬다.
- 모델 지표는 전체 표본과 `model_ms_after_15s`/`drop_pct_after_15s`를 구분한다. 과거 주행 비교에는 같은 초기화 제외 범위를 사용한다.
- 첫 `initData`의 시각은 실제 서비스 시작보다 이를 수 있다. `drive`·`stops`·`tl`의 시간 원점은 첫 비메타 메시지(`initData`·`sentinel` 제외)로 통일했다. 구 보고서의 상대 시각과 바로 섞지 않는다.
- 손상 경고는 보존한다. 가능한 정상 메시지는 분석하되 결과는 부분 분석(2)으로 표시한다.
- qlog의 `modelV2` 부재가 모델 지표 전체 부재를 뜻하지 않는다. `drivingModelData`에서 실행 시간·누락률을 일부 볼 수 있다. 정확한 모델 출력·카메라 간격은 rlog가 필요하다.
- qlog의 `procLog` 샘플률은 버전별로 확인한다. 과거 문서의 고정 0.5 Hz 표현은 철회한다.
- 누락률이 여러 표본에 남아 있다고 그 수만큼 독립 누락 사건이 발생한 것은 아니다.
- qlog Jetlink 오류 0건으로 `waiting` 지속을 증명할 수 없다. 과제 17번은 USB 역할·상태·재시도 이력과 같은 구간의 CPU를 함께 확보해야 하며 자동으로 닫지 않는다.
- noOutput은 단순 속도 0이 아니라 오프로드·점화 상태와 함께 해석한다. 시동 전환 중 noOutput도 즉시 고장으로 단정하지 않는다.
- 파일 mtime은 로그 후보를 찾는 보조 수단이다. 시계 보정 전 기록과 파일 재사용을 고려해 boot ID·부팅창·단조 시각과 대조한다.
