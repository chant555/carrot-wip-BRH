# C4 점검 도구 인계 요약 — 2026-09-28

원본 로컬 HANDOFF와 조사 색인의 개인·장치 정보를 제외하고, 이번 보관 범위에 필요한 결론과 후속 과제를 정리했다. 차량 실행 코드의 변경 지시나 배포 승인 문서가 아니다.

## 보완한 내용

- 빈 입력·누락·손상·실시간 미수신을 정상으로 처리하지 않는다. 오류와 부분 분석을 종료코드 1/2로 구분하고 원격 묶음에 전달한다.
- 로그 손상 경고를 보존하고 읽을 수 있는 앞부분만 집계한다. 세그먼트 내부 메시지는 단조 시각 순으로 정렬한다.
- drive/stops/tl의 시간 원점은 initData/sentinel을 제외한 첫 메시지다. 구 보고서의 상대 시각과 직접 섞지 않는다.
- 정지 후보는 자동 가감속 활성, 페달 개입 없음, 선행차, 결합 자료 신선도 등을 검사한다. 정지 후 유지나 후진 여부는 검사 범위 밖이다.
- CAN 카운터는 DBC 비트 폭에 따라 순환을 계산하며 비연속 세그먼트나 시간 공백을 넘겨 비교하지 않는다. sendcan은 송신 요청 기록이므로 실제 버스 수신·CRC 정상까지 뜻하지 않는다.
- CPU는 공통 관측 시간과 누적 CPU 증분으로 계산한다. 예전의 프로세스별 수명 정규화 합계와 직접 비교하지 않는다.
- Jetlink 상태 신선도·상태 변화·USB 역할을 관측한다. qlog 오류 0건이나 짧은 오프로드 waiting으로 주행 전체의 대기 상태를 입증하지 않는다.
- 파일 수정 시각으로 선택한 부팅 로그는 후보임을 명시한다. 부팅 시계 보정 때문에 실제 부팅창과 다를 수 있다.

## 실제 실행과 최종 도구 버전의 구분

| 검증 | 관측과 한계 |
|---|---|
| 최종 로컬 회귀 | 19개 통과, 정상·빈 입력·손상·누락·시간 결합·카운터·CPU·셸 종료 전달 사례 포함 |
| C4 부팅 묶음 | `addd48d9`에서 MPC 솔버 두 개 import, BRH 스탬프 일치, HTTP 두 포트 200, 필수 프로세스 확인 |
| 부팅 관측 | Panda faults 없음, SPI 추가 증가 없음, Jetlink waiting. 후보 로그 ERROR 8건을 숨기지 않고 묶음은 1 반환 |
| ea 전체 qlog | 시간 정렬 및 초기화 제외 통계 보완 후 실행. 마지막 23번 파일의 손상으로 2 반환 |
| ea 정지 후보 | 조건 충족 1개/제외 5개. 충족 장면은 새 시간 원점 62.954초, 정지 명령 약 −0.5041, 앞차 거리 5.308 m |
| ea 모델 지표 | 초기화 15초 이후 평균 29.7436 ms, 최대 36.9875 ms. 누락률 잔여 표본 1,178개는 독립 사건 수가 아님 |
| ea 10번 rlog | MDPS TX 5,999개 중 비교 5,998개 모두 +1, TCS TX 3,000개 중 비교 2,999개 모두 +1; 새 CPU 합계 442.91% |

실제 부팅 실행 기록은 Jetlink 로그 필터 세분화 전 버전으로, 업데이트 커밋 설명을 Jetlink 예시로 포함할 수 있다. ea 초기 실행과 790초 주변 타임라인은 정렬 보완 전 자료이므로 최종 도구의 정지/타임라인 결과로 사용하지 않는다. ea 전체 최종 실행 이후 추가한 제어 메시지 invalid 분류 및 빈 manager 처리 보완은 로컬 회귀 검사로 확인했다. 최종 도구 전체를 실차 모든 과거 로그에 다시 적용한 것은 아니다.

## 남은 과제

1. e8의 기존 정지 후보 5개를 새 조건으로 재검사하고 정지 후 유지·후진을 별도 확인한다. 기존 인계 과제 15번은 완료로 보지 않는다.
2. Jetlink USB 역할·상태·재시도 이력과 동일 구간 CPU를 주행 중 함께 확보한다. 기존 과제 17번은 계속 미완료다.
3. `addd48d9` 이후 새 주행에서 모델 실행 시간, 카메라 간격·누락, 제어 관련 오류를 같은 분석 범위로 비교한다.
4. SPI 증가 군집과 GPS almanac 저장 실패를 계속 추적한다. 값 감소나 오류 미관측만으로 원인 해결을 단정하지 않는다.
5. MDPS/TCS 전체 구간 연속성, CRC, 실제 버스 전달 여부는 선택 rlog 표본 검증과 분리해 평가한다.
